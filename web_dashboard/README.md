# АгроМонитор — web dashboard

FastAPI backend + React (Vite) frontend за системата за агромониторинг. Реализира dashboard-а и admin панела, обсъдени в `description_updated.docx` (зони, физически модули, потребители).

**Няма enforced login/оторизация все още.** Има `users` таблица и CRUD за нея (таб "Потребители"), но никой API ендпойнт не проверява самоличност — това е следваща стъпка.

По подразбиране базата е локален SQLite файл (`backend/data/app.db`), автоматично създаден и напълнен с примерни данни (4 зони, сензори, клапани, помпи, потребители) при първо стартиране — нулева настройка. За реалния MySQL стек от документацията виж бележката най-долу.

## Изисквания

- Python 3.9+ (тествано с 3.9)
- Node.js 18+ (тествано с 20)

## 1. Backend (FastAPI)

Без venv — директно към системния Python:

```bash
cd web_dashboard/backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

(Ако предпочиташ изолирана среда по-късно, спокойно можеш да добавиш venv — кодът не разчита на нищо специфично.)

API-то е на `http://localhost:8000`, интерактивна документация (Swagger) на `http://localhost:8000/docs`.

При първо стартиране автоматично се създава `backend/data/app.db` и се пълни с примерни зони/модули/потребители (виж `app/seed.py`). За да започнеш от чисто ново състояние, просто изтрий тоя файл.

## 2. Frontend (React + Vite)

Във втори терминал:

```bash
cd web_dashboard/frontend
npm install
npm run dev
```

Отваря се на `http://localhost:5173` и говори с backend-а на `localhost:8000` (конфигурируемо през `VITE_API_URL` в `.env`, ако се смени портът).

## 3. Какво има в интерфейса

- **Табло** (`/`) — карти за всяка зона с gauges (почва/въздух T°/RH), режим на управление, и чипове за клапаните — клик върху чип праща ръчна on/off команда.
- **Admin панел** (`/admin`, бутон горе вдясно) —
  - **Физически модули** — CRUD за сензори, изпълнители, повторители, клапани, помпи, gateway. Добавянето става в отделен модален прозорец; изтриването изисква потвърждение.
  - **Зони** — създаване на зона (модал), назначаване на сензори/клапани (само клапани с вече зададени помпа+изпълнител могат да влязат в зона), inline създаване на нов клапан направо оттук, и бутон **„Настройки“** за конфигуриране на автоматичния режим — часови интервали с избор кои клапани отварят (clock) или прагови правила по параметър с избор кои клапани компенсират (threshold).
  - **Членство в зона само при деактивирана зона** — добавяне/премахване на сензор или клапан е заключено, докато зоната е активна (сървърът го налага, не само интерфейсът) — трябва първо да я деактивираш. Активиране/деактивиране и изтриване искат потвърждение.
  - **Потребители** — CRUD за акаунти и зоново ниво на достъп (view/control), добавянето е в модал.

## Преминаване към MySQL (реалния deployment)

Схемата в `app/models.py` е директно преносима към MySQL. За да смениш от SQLite:

```bash
pip install pymysql
set DATABASE_URL=mysql+pymysql://user:password@host:3306/agromonitor
```

(или `export DATABASE_URL=...` на Linux/Mac) преди да стартираш uvicorn. Таблиците ще се създадат автоматично при първо стартиране (`Base.metadata.create_all`); `seed.py` пуска само ако `zones` е празна, така че е безопасно и за реална база.
